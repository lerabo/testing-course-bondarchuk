# Вимоги до якості (ISO/IEC 25010:2023)

## Розділ 1. Пріоритети характеристик

Зацікавлені сторони: **деканат** (правильні відомості, звітність), **викладачі** (швидке й безпомилкове виставлення балів), **студенти** (бачити свої оцінки, захищеність даних), **університет / ІТ-відділ** (відповідність закону, стабільна робота, простий супровід).

| Пріоритет | Характеристика ISO/IEC 25010:2023 | Зацікавлені сторони | Обґрунтування |
|-----------|-----------------------------------|---------------------|---------------|
| 1 | Функціональна придатність | Деканат, викладачі, студенти | Головне призначення — правильна оцінка ECTS і відомості; помилка впливає на стипендію та відрахування. |
| 2 | Безпека | Студенти, університет | Персональні дані й оцінки захищені законом; зміни оцінок мають бути підзвітні. |
| 3 | Надійність | Викладачі, деканат | Оцінки виставляють у короткі періоди сесії; збій або втрата даних у цей час критичні. |
| 4 | Ефективність продуктивності | Викладачі, деканат | Під час сесії навантаження пікове, відомості формуються масово. |
| 5 | Здатність до взаємодії | Викладачі | Викладачі — не ІТ-фахівці; помилка введення (не той студент) дає неправильну оцінку. |

**Найменш важливі:** *Гнучкість* (flexibility) — застосунок розгортається в одному середовищі університету, перенесення не планується. *Безпечність* (safety) — система не керує обладнанням і не загрожує життю чи здоров'ю людей.

## Розділ 2. Вимірювані вимоги

| ID | Характеристика / підхарактеристика | Вимога | Метрика і цільове значення | Умови вимірювання | Спосіб перевірки |
|----|-----------------------------------|--------|----------------------------|-------------------|------------------|
| ЯВ-01 | Функціональна придатність / коректність | Оцінка ECTS обчислюється за шкалою з Д-04 | Частка правильних оцінок для всіх цілих балів 0–100 — 100 % (101 із 101) | Модульний рівень, функція перетворення балів | Модульний параметризований тест, pytest |
| ЯВ-02 | Безпека / конфіденційність | Студент не отримує даних і оцінок інших студентів | 100 % запитів студента до чужих `/api/students/{id}` і `/grades` повертають 403 | Тестова БД, 2 студенти різних груп, усі ендпоінти з таблиці API | Тест API (інтеграційний), httpx; OWASP ZAP |
| ЯВ-03 | Безпека / підзвітність | Кожна зміна оцінки потрапляє в журнал | 100 % змін мають запис (хто, коли, старе, нове значення) | 50 змін оцінок через API від різних викладачів | Інтеграційний тест, перевірка таблиці журналу |
| ЯВ-04 | Безпека / автентичність | Захист від підбору пароля | Після 3 невдалих спроб за 15 хв четверта спроба (навіть із правильним паролем) відхиляється протягом 15 хв | Тестовий стенд, один обліковий запис | Системний тест API |
| ЯВ-05 | Надійність / доступність | Система доступна в робочому режимі | ≥ 99,5 % за календарний місяць без планових робіт | Продуктивне середовище, перевірка кожні 60 с | Моніторинг (UptimeRobot), приймальний звіт за місяць |
| ЯВ-06 | Ефективність продуктивності / часова поведінка | Список студентів групи відкривається швидко | 95-й процентиль часу відгуку `GET /api/students?group=` ≤ 300 мс | 200 одночасних користувачів, у БД 5000 студентів, 10 хв | Навантажувальний тест, Locust |
| ЯВ-07 | Ефективність продуктивності / часова поведінка | Швидке формування відомості | Відомість PDF і XLSX для групи з 40 студентів ≤ 5 с | 10 одночасних запитів звіту | Системний тест продуктивності, Locust |
| ЯВ-08 | Здатність до взаємодії / захист від помилок користувача | Викладач безпомилково виставляє бали | ≥ 4 з 5 викладачів виставляють оцінку за ≤ 2 хв без помилок у виборі студента | Без попереднього навчання, тестовий набір із 30 студентів | Юзабіліті-тест (приймальне тестування) |
